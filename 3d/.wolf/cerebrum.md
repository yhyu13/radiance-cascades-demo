- [2026-05-06] `OBJLoader::load()` did NOT clear arrays before parsing — appended new geometry onto old. Always add `vertices/normals/texcoords/faces/faceMaterials.clear()` at the top of `load()` when adding any new OBJ load path.
- [2026-05-21] Cascade merge is done at **bake time** (cascade i's compute shader reads `uUpperCascadeAtlas` from cascade i+1 and blends), NOT at consume time. The raymarch frag consumes only the lowest active cascade — it cannot independently choose to "skip" or "renormalize." Any per-cascade attribution / leave-one-out feature MUST be implemented as bake-chain rewiring (skip dispatch + shift `upperIdx5d` + extend `cnMinRange`), not consume-time math. See `doc/7/mbrc_v20_pre_measurement_impl.md` §2.
- [2026-05-22] **Before estimating engine work for a measurement discriminator, read the shader for already-shipped toggle uniforms first.** The (β) impl doc estimated "~2-3h engine work" for the (α) merge-mode A/B sweep, assuming a new `uUseIsotropicMerge` uniform and new shader code path. - [2026-05-19] **Per-pixel diagnostics required when averaged metrics mask compositional errors.** Mode 18 (cascadeTotal − PTTotal) on cornell-orig + directional light showed mostly white — looked like cascade matched PT. - [2026-05-21] **PT-reference dispatch gates must list every render mode that READS uPtAccum / uPtDirectAccum, not just modes that DISPLAY PT.** bug-227 ([demo3d.cpp:1244](../src/demo3d.cpp#L1244)) — the gate was `mode==16 || 18 || 19`; mode 20 (Error-Decomposition Heatmap) reads BOTH accumulators but was never added to the gate. - [2026-05-22] **GUI-vs-headless control-flow divergence is the most likely silent-fail surface for "feature works in interactive but produces identical output in measurement runs".** bug-234: Phase MB temporal feedback gated on `useMultiBounce && hasPrevFrame && !historyNeedsSeed`. - [2026-05-22] **Named-hypothesis-tree exhaustion is a verdict, not a failure.** The MBRC v2.0-pre sweep program enumerated 4 named hypotheses (α, β, γ, δ) for the cascade-vs-PT asymmetric Δ pattern; all 4 have now been eliminated by pre-committed discriminator rules with a mix of REJECT (γ, δ — "knob has no leverage") and LEVERAGE_NOT_CURE (β, α — "knob has leverage but cannot eliminate the residual"). - [2026-05-20] **"NEE" in real-time renderers should mean light-position sampling with solid-angle pdf, NOT a cone aimed at the light direction.** v1.3 hybrid named its DI-cone (cosine-weighted cap around `lightDirFromP`) "NEE" — the variance sweep then shipped 200 frames per arm showing **−0.01% improvement** (statistical tie) on cornell-orig-alcove, the scene chosen as the best shadow-boundary test. Why: on top-lit floor pixels the cone axis ≈ surface normal, so cone sampling degenerates to ≈cosine sampling; on side-wall pixels `nDotL ≤ 0 → α=0` gates out the cone entirely. The two paths converge to the same estimator and no variance is reduced. Visual A/B between arms is also identical (correct — one-sample MIS preserves expectation), so without the variance harness this would have shipped as "working." **Rule:** if you build a "shoot toward the light" sampler that uses the same hemisphere coordinate frame as the BRDF (cosine-weighted upper hemisphere), you have a *directional importance cone*, not classical NEE. Naming it NEE is misleading — true NEE picks a point on light geometry, evaluates solid-angle pdf to that point, and gets variance reduction proportional to how much smaller the light's solid angle is than the BRDF lobe. The directional-cone variant only helps when the light is small AND the BRDF is glossy AND `nDotL > 0` — three conditions cornell-orig-alcove fails simultaneously. See [doc/7/hybrid_v12_validation_phase8_impl.md §10.4](../doc/7/hybrid_v12_validation_phase8_impl.md) for full data.

## Decision Log

- **Non-co-located probes (Phase 5d):** Chosen over co-located for better GI accuracy at cascade boundaries; trilinear upper-cascade lookup needed as a result
- **Two-script RenderDoc architecture (Phase 6b):** qrenderdoc embeds Python 3.6 which can't use modern `anthropic` SDK. Solution: rdoc_extract.py runs in qrenderdoc, analyze_renderdoc.py runs separately with regular Python
- **Probe jitter excluded from default (Phase 9):** Full cascade rebuild per jittered frame too expensive at 32³ probes × 4 cascades
- **Bilateral blur over tricubic (Phase 9d):** Tricubic needs 64 fetches vs 8; blur achieves similar smoothing at a fraction of the cost
- **Analytic SDF over mesh SDF (Phase 0/7):** Toggle exists; analytic is default for speed + correctness; mesh SDF from `sdf_3d.comp` is optional
