# 不要拿「看起来像路径追踪」当全局光照正确

做 3D 全局光照，最容易走错的一步，不是公式写错，而是把三件不同的事揉成一句：「这算法对不对？」

图像亮一点、暗一点、墙红了、盒子黑了——这些是观感。探针方向数够不够、小灯会不会撑满一个立体角——这些是近似度。一帧 GPU 打了多少 thread——这是实现成本。

它们不该共用一个旋钮。共用的结果，我已经付过一次学费：对着路径追踪调 gain、调 floor、调可见性代理，调了三十多个提交，整条线判死刑。

后来我们把 ShaderToy 上那套表面附着的 Radiance Cascades 做成默认内核。门禁过了，并不等于质量可控，更不等于性能已知。下面是从那次翻车里拆出来的三层定义。可以搬走的是判断，不是文件名。

---

## 先分清你在跑哪条算法

仓库里同时活着两套 3D RC。名字都叫级联，证据不能混用。

![左边是默认的表面 RC，右边是必须显式打开的体网格 RC；两条路径的数字不能互相当成绩单](images/01-two-paths.png)

左边是现在的默认路径：探针长在表面上，半球往法线一侧打，合并发生在表面参数空间。这是对 ShaderToy 参考实现的语义移植。

右边是旧的体网格：探针铺在空里，八面体扫全方向，靠 SDF 步进。它有自己的审计、自己的毫秒数、自己的 α 通道争论。那些数字描述的是另一套算法。

把体网格的 bake 耗时拿来指导表面 RC 的优化，等于拿邻班的期中成绩改自己的复习计划。对象错了，后面全错。

---

## 正确、质量、性能，红了停在本层

我们后来把「对不对」拆成三层。每一层有自己的证据，也有自己的失败动作。

![三层控制面：语义门禁、命名质量档、GPU 基线；红了只许停在本层](images/02-three-layers.png)

**第一层是语义。** 参考实现的公式、探针布局、上层合并、跨帧反馈、payload 合同，必须能被独立夹具证伪。我们用三层对照：一份从参考着色器推出来的双精度黄金数据，一份生产代码的 CPU 镜像，一份真正上 GPU 的 shader。一层不同意上一层，门禁失败。CPU 自己跟自己比，不算证据。

这一层过了，只说明 port 复现了参考公式。不说明图像等于路径追踪，更不说明适合任意网格。

**第二层是质量。** 路径追踪对比是报告，不是门禁。我们测过：同一套 Cornell、同一相机，表面 RC 的线性亮度大约是路径追踪的 1.08 倍。那 8% 到 13%，来自参考算法自己的最细一层只有 2×2 个方向——半球被切成四块。小灯打进其中一块，就会被当成填满这块的立体角。这是算法上限，不是移植写错。

**第三层是性能。** 没有本算法的 GPU 基线，不许谈优化。体网格那条路径的 cascade 耗时，描述的不是这条默认路径。

三层的纪律就一句话：

- 语义红了，算法坏了，停。更好看、更快，都不能覆盖。
- 语义绿、质量差，只许换命名档，不许改锁定常量。
- 语义绿、实现贵，只许动 dispatch、格式、跳过空转。不许加 gain。

「看起来更像路径追踪」如果被当成正确性，人就会去拆第一层的期望值。那正是上一轮失败的机制。

## 质量旋钮在耦合上，不在增益上

参考实现把空间密度和角分辨率锁在同一个幂次上：

`probeSize = 2^(cascade + 1)`

最细一层 `probeSize = 2`，所以 2×2。加倍 `probeSize`，方向数乘四，空间探针除四，总成本同阶。这不是疏忽，是这套算法的定义。

因此，在锁定场景上把最细一层改成 4×4，不是「提高质量」，是「拆掉语义门禁」。合法做法是另开一档，黄金数据另做一份，路径追踪报告另记一笔。

![Parity 档锁死 2×2 并独享语义门禁；High-C0 只改 shader 偏移，不改锁定头文件](images/03-quality-knobs.png)

我们现在的默认档叫 parity，唯一能过语义门禁。另一档叫 high-c0：只在 shader 里加一个对数偏移，头文件里的锁定常量不动。验证程序遇到 high-c0 直接拒绝。它存在的意义是压小灯 alias，不是去「修移植」。

下面这些东西看起来像质量旋钮，其实是上一轮的遗物：增益、辐照度地板、代理可见性、对称邻域夹紧、改门禁期望值、用 PNG 观感推进。每一项都曾让人觉得「亮了就是对了」。每一项后来都被测量打回。

过滤怎么选，也不是口味。距离写在 alpha 里，线性过滤会把天空哨兵和命中距离搅在一起。我们做过 A/B：两种过滤语义门禁都过，能量差 0.08%。生产默认跟参考实现的 cubemap 采样走，记成一条故意分歧，而不是悄悄改合同。

## Inactive 是一块矩形，不是探针变稀疏

默认场景的物理图集是 1024×512，六个级联，每帧从上往下打满。Inactive 比例稳定在 37.5%。形状不是「很多探针没活」，而是内页右下角整整一块 padding：`x ≥ 256` 且 `y ≥ 256`。

所以第一刀不是稀疏 worklist。第一刀是拆 dispatch：主页整宽打一次，内页只打左边 256×256。线程少 37.5%。语义门禁的像素误差和拆之前相同。

![全图集右下角 37.5% 是 padding；拆成两次 dispatch 后不再启动那块线程](images/04-split-dispatch.png)

GPU 计时有坑。同一套 replay，Duration 能抖两到五倍。拆之前那次 capture 级联耗时甚至不是单调的。所以不要拿两次 Duration 相除，对外宣称加速了四点八倍。能写进报告的只有线程数和门禁误差。当前生产基线是拆完之后的那份 JSON。

还想再快，必须先有数字：带宽不够再动生产路径的存储格式；远场级联贵再考虑隔帧。没有新的基线，就没有下一刀。

## 网格泛化要带着预算出门

语义内核做完之后，下一件诱人的事是把硬编码的 Cornell 平面换成真网格。Sponza、UV2、三角岛，听起来才像产品。

问题是：chart 数量和 primitive 数量会一起跳。没有 Cornell 上的控制面，慢了你不知道是 trace 贵了、图集大了，还是门禁被悄悄拆了。

所以顺序是先控制面，再 packer，再 tracer。

![Phase 0 到 10 证明公式；Phase 12 立控制面；然后才允许 CPU packer 和带预算的网格实跑](images/05-roadmap.png)

网格阶段的预提交条件也很硬：质量只用 HDR EXR，不用 PNG 观感；性能相对拆 dispatch 后的 JSON 给倍数；Sponza 不准用盒子代理冒充表面 RC。混用三层，或者用截图推进，直接停。

---

## 能搬走的四句话

1. **先锁对象。** 默认路径和遗留路径不是同一个算法。数字必须标明来自哪一条。
2. **正确不是观感。** 语义门禁证明公式；路径追踪证明近似度；GPU 计时证明成本。三层红了停在本层。
3. **质量换档，不改锁定常量。** 空间和角度的幂次耦合是定义。增益、地板、代理可见性不是定义。
4. **性能先测量，再动实现。** Inactive 的形状决定杠杆。Duration 会抖，线程数和门禁误差不会。

树叶会改名、搬家、重写。这四句如果对了，换一套级联实现也还是同一套判断。如果错了——拿观感当正确、拿邻班的毫秒数当基线、拿增益当质量——叶子写得再漂亮，下一轮调参仍会在同一处裂开。
